Build and deploy a Python Flask web application called "Public Sector Procurement Monitor". This is a tool for a sales team to track government procurement opportunities that match a watchlist of previously lost deals.

## Core Functionality

The app monitors SAM.gov (the federal procurement API) and matches opportunities against a configurable watchlist of government agencies. It uses keyword and NAICS-code-based searches, scores matches with fuzzy matching, and surfaces alerts in a dashboard.

## Tech Stack

- **Backend**: Python, Flask
- **Frontend**: HTML/CSS/JS (no framework needed — clean, modern UI with Tailwind CSS)
- **Database**: SQLite (via SQLAlchemy) to store watchlist entries, alerts, scan history, and config
- **Task scheduling**: APScheduler (for automated daily scans)
- **External API**: SAM.gov Opportunities API v2 (https://api.sam.gov/opportunities/v2/search)

## Pages / Routes

- Summary stats cards: total alerts, high-priority alerts, unique agencies matched, total pipeline TCV

- Filter controls: priority level, date range, agency, minimum match score

### 2. Watchlist Management (`/watchlist`)
- Table of all watchlist entries showing: agency name, state, TCV, loss reason, competitor, rebid window, priority, notes
- Add/Edit/Delete watchlist entries via modal forms

- Import from Excel (.xlsx) upload — parse agency data from a GPM Win/Loss export
- Color-code rows by priority

### 3. Run Scan (`/scan`)
- Button to trigger a manual scan
- Options: scan window (days back, default 30), toggle keyword search, toggle NAICS-only search
- Live progress log showing scan activity (use server-sent events or polling)

### 4. Settings (`/settings`)
- SAM.gov API key (stored securely as environment variable, UI just shows if configured)

### 5. Analytics (`/analytics`)

## SAM.gov Integration

The SAM.gov Opportunities API v2 endpoint is: `https://api.sam.gov/opportunities/v2/search`

Parameters:
- `api_key`: from environment variable `SAM_API_KEY`
- `limit`: max 1000
- `offset`: for pagination
- `postedFrom` / `postedTo`: date range in MM/DD/YYYY format
- `title`: keyword to search in opportunity title
- `ncode`: comma-separated NAICS codes

Two search strategies:
1. **Keyword search**: iterate each search keyword as the `title` param
2. **NAICS-only search**: broader sweep using only NAICS codes, no title filter

Deduplicate results by `noticeId`. Handle rate limiting (429 status → wait 60s and retry). Paginate through all results.

## Matching Engine

For each SAM.gov opportunity, combine `title + description + department/fullParentPathName` into one text blob. For each watchlist entry:
1. Score the text against the entry's `search_terms` using word-overlap matching (normalize text: lowercase, strip punctuation, compare word overlap)
2. Add +0.2 bonus if the text also contains any global search keyword (e-signature, CLM, etc.)
3. If score >= threshold (default 0.4), create an alert

## Data Model

**WatchlistEntry**: id, agency, search_terms (JSON array), state, tcv, reason, competitor, rebid_window_start, rebid_window_end, priority, notes, created_at, updated_at

**Alert**: id, timestamp, source, agency_match (FK to watchlist), opportunity_title, solicitation_number, posted_date, response_deadline, url, match_score, watchlist_tcv, watchlist_priority, notes

**ScanLog**: id, started_at, completed_at, scan_window_days, total_opportunities, total_alerts, status

**Config**: key-value store for settings
